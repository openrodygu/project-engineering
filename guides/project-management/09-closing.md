# Closing

Confirm the result, hand it over cleanly, and leave the next team with context instead of loose ends.

## Close against the definition of done

Closing is not the moment work stops. It is the moment the team agrees the result is accepted.

1. Open the definition of done from the brief.
2. Check each item with evidence, not memory.
3. Get the decision maker to accept the result.
4. Record any remaining gaps and who owns them.

If an item is not met, either finish it, move it to a follow-up, or change the definition with the decision maker. Do not quietly lower the bar.

## Hand over

A handover is a short note that lets someone run the result without asking you.

```markdown
**What was delivered:** ...
**Where it lives:** ...
**How to use it:** ...
**Known limits:** ...
**Who to contact:** ...
**Open follow-ups:** ...
```

Keep it practical. A link to the repository, the run steps, and the known limits are worth more than a long summary.

## Write a close-out note

The close-out note is the project's final record. One page is enough:

- Outcome and whether it met the definition of done.
- Start and end dates.
- Actual effort compared with the estimate.
- What changed from the original plan.
- Key decisions and links.
- What the team would do differently.

This is the note someone reads in a year when they ask, "Why was this built this way?"

## Retrospective

Spend 30 minutes on four questions:

1. What went well? Keep doing it.
2. What did not? Name the cause, not the person.
3. What will we change? Pick one or two concrete changes.
4. What did we learn? Link the notes and decisions.

A retrospective with ten actions changes nothing. A retrospective with one action that gets adopted is a success.

## Archive

Move finished work out of the active view without deleting it.

- In dotpm, set accepted tasks to Done, archive them, and archive the project when it is truly finished.
- Move remaining open tasks to Cancelled or a follow-up project.
- Keep the brief, the close-out note, and the decision records.
- Delete only duplicates and noise, not history.

An archived project is still searchable. A cluttered board is not useful.

## Try it

Close one small piece of work.

1. Check the definition of done and record the evidence.
2. Write the handover note.
3. Write the close-out note with actual effort and one lesson.
4. Archive the completed tasks in `local-project/pm-vault/`.
