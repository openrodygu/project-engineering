# Lifecycle

Use phases to make progress visible without turning the project into paperwork.

## The four phases

Most projects move through four phases, even when the names differ:

1. **Initiate** — confirm the problem, the outcome, and the people who decide.
2. **Plan** — break down the work, estimate it, sequence it, and set the first commitments.
3. **Execute** — do the work, track reality, and adjust the plan.
4. **Close** — confirm done, hand over, capture lessons, and archive.

These are not gates you must pass in a fixed order. They are modes of work. A small project may spend an hour in planning and weeks in execution. A large one may revisit planning every few weeks.

## Phase exits

Each phase should end with something observable:

| Phase | Exit artifact |
| --- | --- |
| Initiate | A one-page brief with an outcome and a definition of done |
| Plan | A task board with owners, dates, and dependencies |
| Execute | Accepted deliverables and current status |
| Close | A close-out note and an archived project |

If you cannot name the exit artifact, the phase is not finished. That is useful information, not a failure.

## Plan in slices

Long plans go stale. Plan the whole project at a high level, then plan the next slice in detail.

- High level: milestones, major deliverables, dependencies, risks.
- Next slice: tasks someone can start this week.

This keeps the plan honest without requiring a perfect forecast. The near-term work is specific. The distant work is a direction.

## Gates for decisions, not ceremony

Use a gate when a real decision is needed:

- A budget release.
- A go/no-go on a vendor.
- A sign-off before a public launch.

Do not add a gate just to schedule a meeting. Gates cost time. Keep them where the cost buys a real decision.

## Iterate when the work is uncertain

If the outcome is clear but the path is not, work in short cycles: plan, build, review, adjust. If the outcome is vague, spend more time in initiate. Building the wrong thing faster is not progress.

## Try it

Take a current project and place it in one phase.

1. Name the exit artifact for that phase.
2. Write the next decision that needs a gate, if any.
3. List the next slice of work you can plan in detail.

Add the phase and next gate to your project brief.
