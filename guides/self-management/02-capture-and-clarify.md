# Capture and clarify

Capture is fast. Clarify is deliberate. Mixing them is why inboxes become graveyards.

## Capture

When something shows up, write it down in one place. Do not decide the project, the priority, or the date while you are in the middle of something else.

In TaskNotes, capture with **TaskNotes: Create new task** from the command palette. Natural language is enough:

```text
Follow up with Vendor B about pricing tomorrow @office
```

The task lands in `TaskNotes/Tasks` with a title and a scheduled date. You can fill in the rest later.

Capture is not a commitment. It is a note to yourself that the thing exists.

## Clarify

Clarify each item with a few questions:

1. **Is it actionable?** If no, it is a reference note, a waiting item, or nothing.
2. **What is the next action?** Start with a verb: "Email", "Draft", "Call", "Review".
3. **Where or how?** Add a context such as `office`, `home`, `deep-work`, `email`, or `waiting`.
4. **How long?** Add a rough estimate in minutes.
5. **When?** Set `scheduled` for intent. Set `due` only for a real deadline.
6. **What does it support?** Link a project note if there is one.

If the next action takes more than one sitting, break it into a smaller action.

## The two dates

This is the most useful distinction in TaskNotes:

- **`scheduled`** — when you intend to work on it.
- **`due`** — when it must be finished.

Putting a due date on everything creates fake urgency. Most tasks need a scheduled date and no due date at all.

## Waiting items

If the next action belongs to someone else, mark it `waiting`. Write who owns it and when you will follow up in the task body.

```text
Waiting on: pricing sheet from Vendor B.
Owner: Dana
Follow up: 2026-11-10
```

Review `waiting` items weekly. Otherwise you are waiting forever.

## Try it

Take five items from your inbox and clarify them. For each one, write the next action, add a context, and set a scheduled date. Move anything that is not actionable to a reference note or delete it.
