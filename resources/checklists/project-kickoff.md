# Project kickoff checklist

Use this before the first task. Keep the answers short and put them in the [project brief](../templates/project-brief.md).

## Before the kickoff

- [ ] Name the project in one sentence.
- [ ] Write the outcome: what will be true when this is done?
- [ ] List what is in scope and what is out.
- [ ] Name the owner and the people who must agree.
- [ ] Identify the first milestone and its date.
- [ ] Note known dependencies and risks.
- [ ] Decide where the team view will live.

## In the kickoff

- [ ] Read the outcome and scope aloud.
- [ ] Agree on the definition of done.
- [ ] Break the first milestone into tasks.
- [ ] Give every task an owner and a status.
- [ ] Agree on the review cadence.
- [ ] Agree on how decisions will be recorded.
- [ ] Agree on how status will be shared.
- [ ] Ask what could make this fail.

## After the kickoff

- [ ] Share the brief with the team.
- [ ] Create the tasks in the shared view.
- [ ] Put your own tasks in your personal view.
- [ ] Schedule the first weekly review.
- [ ] Record the first decision if one was made.
- [ ] Set a date to check scope and risk again.

## Done when

- [ ] Anyone on the team can state the outcome and the next milestone.
- [ ] Every committed task has an owner.
- [ ] The first review is on the calendar.
