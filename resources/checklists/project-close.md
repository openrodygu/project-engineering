# Project close checklist

Use this when the outcome is delivered or the project is stopped. Close the same way in both cases.

## Deliverable

- [ ] Confirm the outcome against the definition of done.
- [ ] Get acceptance from the people who must agree.
- [ ] Confirm the handoff owner and date.
- [ ] Note anything deliberately left out.
- [ ] Update the project brief with the final state.

## Work

- [ ] Close or cancel every open task.
- [ ] Archive finished work.
- [ ] Resolve or transfer open dependencies.
- [ ] Remove stale links and views.
- [ ] Confirm nothing important lives only in a personal vault.

## Knowledge

- [ ] Record the decisions that shaped the result.
- [ ] Write down what would be done differently.
- [ ] Save the final links and artifacts in one place.
- [ ] Note the assumptions that proved wrong.

## People

- [ ] Thank the people who helped.
- [ ] Share the result with the stakeholders.
- [ ] Run a short retrospective.
- [ ] Capture one change to keep for the next project.

## Retrospective questions

1. What went well?
2. What did not?
3. What did we learn?
4. What will we keep, change, or drop?

## Done when

- [ ] The result is accepted or the stop is explained.
- [ ] No active tasks remain.
- [ ] The reasoning is saved.
- [ ] One improvement is written down.
