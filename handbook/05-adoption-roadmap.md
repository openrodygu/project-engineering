# Adoption roadmap

A system grows in layers. Do not adopt all of it on day one.

## 30 days

Goal: make work visible.

- Pick one project.
- Create a task board.
- Give every task an owner and a status.
- Run one weekly review.
- Record one decision.

Success: the team can answer “what are we working on?” without asking one person.

## 60 days

Goal: make the flow predictable.

- Break large tasks down.
- Add dependencies where they are real.
- Start using a definition of done.
- Add a short status update.
- Review blockers weekly.

Success: the team can see what is blocked and what is next.

## 90 days

Goal: make the system learn.

- Review estimates against actuals.
- Add a simple metric or two.
- Run a retrospective.
- Archive finished work.
- Write down the practices you are keeping.

Success: the team changes the system based on evidence.

## The adoption levels

| Level | Description | Typical sign |
| --- | --- | --- |
| 0 | Ad hoc | Work lives in chat and memory |
| 1 | Visible | A shared list exists and is current |
| 2 | Consistent | Work moves through a known workflow |
| 3 | Predictable | Estimates and dependencies are useful |
| 4 | Learning | Reviews change the system |

Most teams do not need to reach level 4 on every project. Pick the level that fits the risk.

## What to avoid

- Adopting five tools at once.
- Writing a process document nobody reads.
- Measuring everything.
- Copying a large company’s system into a small team.
- Treating the roadmap as a deadline.
