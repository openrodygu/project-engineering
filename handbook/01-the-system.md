# The system

A project engineering system has four pillars. Each pillar has skills, artifacts, and a place in the templates.

## The four pillars

| Pillar | Question it answers | Skills |
| --- | --- | --- |
| **Workflow** | How does work move from idea to done? | Git, git services, collaboration |
| **Communication** | How do status, decisions, and feedback travel? | Collaboration, team lead |
| **Knowledge** | How does context survive? | Project management, Obsidian |
| **Planning and tracking** | How is work broken down, sequenced, and measured? | Project management, self-management |

## How the skills map

- **Git** — version control and local history.
- **Git services** — hosting, issues, pull requests, review.
- **Obsidian** — the shared and personal vaults.
- **Project management** — planning, communication, execution, metrics, closing.
- **Collaboration** — working with other people in a shared repo.
- **Team lead** — leading people, not just work.
- **Self-management** — running your own execution.

## The artifacts

A system becomes real when it produces artifacts:

- A project brief.
- A task board.
- A decision record.
- A status update.
- A weekly review.
- A retrospective.
- A workspace the team can open.

If a practice produces no artifact, it is probably a habit, not a system.

## The cadence

A lightweight cadence is enough:

- **Daily:** update your own work.
- **Weekly:** review the board, blockers, and next week.
- **Per milestone:** check scope, risk, and decisions.
- **Per project:** close, reflect, archive.

You do not need a meeting for every step.

## The tools

The repo is Obsidian-first:

- **dotpm** for team visibility.
- **TaskNotes** for personal execution.
- **Bases** for views.
- **Git** for version control.
- **GitHub** for hosting and collaboration.

The concepts work without these tools. The templates are one way to adopt the system.
