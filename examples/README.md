# Examples

These walkthroughs show how the skills fit together in practice. They are examples, not rules. Take the parts that fit your situation.

## Pick an example

- [Solo PM](solo-pm.md) — one person running a project with a light setup.
- [Small team](small-team.md) — three to five people sharing visibility.
- [Example Project case study](example-project-case-study.md) — a full project from kickoff to retrospective.
- [Scaling](scaling.md) — what changes with several teams and projects.

## What stays the same

Across all four examples:

- One project has one outcome and a finish line.
- The shared view holds what the team needs to see.
- Personal views hold private execution detail.
- Decisions and reasoning are written down.
- Work is reviewed on a cadence.
- Finished work is closed and archived.

## What changes

The size of the team changes how much structure is useful. A solo project needs a brief and a task list. A small team needs a shared view and a short review. Several teams need a portfolio view, cross-project dependencies, and a program cadence.

Add structure when a real problem appears. Remove it when it stops earning its place.
